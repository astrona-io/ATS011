# Question

Solve this question against the `kind` cluster provisioned for this lab. Kyverno is already installed and running in the `kyverno` namespace. Bootstrap has also pre-created a central namespace called `platform-config`, containing a `ConfigMap` named `shared-ca` — this is your source of truth. This capstone combines both generation techniques from this section's module.

Write and apply one or more `ClusterPolicy` resources, all triggered on `kind: Namespace`, that together govern every *new* namespace cluster-wide (you do not need to worry about `kube-system`, `kube-public`, `kube-node-lease`, `kyverno`, `local-path-storage`, or `platform-config` itself — excluding them is recommended but not required for grading):

1. **Data-based generation:** Every new Namespace must receive a generated `NetworkPolicy` named `default-deny-ingress` with:
   - `spec.podSelector: {}`
   - `spec.policyTypes: ["Ingress"]`

2. **Clone-based generation with synchronize:** Every new Namespace must also receive a `ConfigMap` named `shared-ca`, generated by **cloning** (`generate.clone`, not `generate.data`) the `shared-ca` ConfigMap that lives in `platform-config`. This clone rule must set `synchronize: true`.

You may split this across as many rules or policies as you like, and name everything however you like. Think carefully about what `synchronize: true` actually guarantees before you decide whether any extra plumbing (owner references, finalizers, etc.) is needed — you may find it guarantees more than you expect.
